# ERP

회사 내부용 ERP MVP입니다. FastAPI 백엔드, 정적 프론트엔드, Obsidian Markdown Vault 저장 구조로 구성되어 있습니다.

## 실행

```powershell
python run.py
```

브라우저에서 `config.yaml`의 `server.host`와 `server.port`에 맞춰 접속하면 됩니다. 기본값은 `http://127.0.0.1:8010`입니다.

## 로컬 설정

실행 IP, 포트, reload 여부는 `config.yaml`에서 관리합니다. 이 파일은 로컬 전용이라 Git에 올라가지 않습니다. 공유용 기본값은 `config.example.yaml`을 참고하면 됩니다.

```yaml
server:
  host: 127.0.0.1
  port: 8010
  reload: true

vault:
  path: vault
```

`gai_erp` 가상환경을 직접 지정해서 실행할 때는 다음 명령을 사용합니다.

```powershell
C:\Users\sim\anaconda3\envs\gai_erp\python.exe run.py
```

## Public / Private

왼쪽 메뉴에서 **PRIVATE · 나의 업무**와 **PUBLIC · 함께 쓰는 공간**을 구분합니다.

- **Private**: 작업 타임라인, 할 일. 로그인 계정마다 등록·조회·수정·삭제하며 대시보드의 할 일과 진행 작업도 본인 기록만 집계합니다. 자동 이월, 순서 변경, 하위 작업, 주간 보고서에도 같은 기준을 적용합니다. 관리자도 자신의 개인 기록만 조회합니다.
- **Public**: 캘린더, 연차·반차·재택, 뽀모도로 실행 기록, 프로젝트, 팀 채팅, 영수증, 재택근무 기록, 회의록, 자료실, Info. 로그인 사용자들이 함께 조회합니다. 대시보드의 일정·회의·부재·프로젝트도 공용입니다.

개인 기록은 담당자 이름과 별개로 계정의 고유 `user_id`를 Obsidian frontmatter에 저장합니다. 이름이 같거나 담당자를 수정해도 소유 계정은 바뀌지 않습니다. 등록 계정이 없는 기존 작업·할 일·주간 보고서는 최초 전환 시 admin 계정에 보관하며 기존 내용·경로·기록 시간은 유지합니다.

노트 상담봇도 본인 개인 기록과 공용 자료만 검색합니다. 전체 파일을 읽을 수 있는 기존 Codex SDK 실행은 개인 기록 분리와 양립하지 않아 중단하고, 상담봇은 로컬 검색, 주간 보고서는 로컬 집계로 제공합니다. 기존 SDK 환경변수로 다시 활성화되지 않습니다. 도구 훅만으로는 완전한 접근 제한을 보장할 수 없습니다([공식 문서](https://learn.chatgpt.com/docs/hooks#tool-coverage)).

## 로그인과 관리자

`/login`에서 로그인합니다. 초기 관리자 ID는 `admin`이며 비밀번호는 요청 시 지정한 값으로 설정됩니다. 관리자 로그인 후에는 `/admin`으로 이동하고, **ID / 비밀번호 / 이름 / 직함**을 입력해 일반 사용자 계정을 등록합니다. 비밀번호는 8자 이상이며 목록에 표시하지 않습니다. 일반 사용자는 로그인 후 대시보드로 이동하고 관리자 화면과 계정 API에는 접근할 수 없습니다.

영수증 등록 화면을 포함한 ERP 페이지·데이터·첨부 파일에는 로그인이 필요합니다. 상단에 로그인한 이름·직함과 로그아웃 버튼을 표시합니다. 로그인은 12시간 유지되며 로그아웃 시 서버 세션도 폐기합니다. 계정과 세션은 `vault/Auth/auth.sqlite3`에 저장하고 Git에서 제외합니다. 비밀번호는 개별 salt를 사용하는 PBKDF2 해시로 저장하며 재시작해도 계정은 유지됩니다.

영수증 등록자, 재택근무 작성자, 뽀모도로 사용자, 채팅 이름은 로그인 계정에서 자동으로 채웁니다. 서버에서도 로그인 이름을 사용하므로 요청에 다른 이름을 넣어 사칭할 수 없습니다. 기존 기록의 작성자 이름은 유지합니다. 작업·프로젝트 담당자와 새 일정·회의록 참석자는 로그인 이름을 기본값으로 제공하고 업무 배정이나 다른 참석자 입력을 위해 수정할 수 있습니다. 뽀모도로의 브라우저 저장 상태와 미전송 기록은 계정별로 구분합니다.

## 페이지

왼쪽 **ERP 로고 오른쪽의 접기 아이콘**으로 메뉴를 닫습니다. 접힌 상태에서는 본문 왼쪽 위의 **> 버튼**으로 다시 펼칩니다. 메뉴를 접으면 본문이 넓어지며, 선택한 상태는 브라우저에 저장되어 새로고침 후에도 유지됩니다. 메뉴를 여닫아도 현재 화면의 입력 내용과 실행 중인 타이머는 유지됩니다.

메뉴 왼쪽 **점 6개 손잡이**를 잡아 드래그하면 표시된 선 위치로 순서를 변경합니다. **Private는 Private 안에서, Public은 Public 안에서만** 이동할 수 있고 대시보드는 고정입니다. 손잡이에 키보드 포커스를 두고 방향키로 옮길 수도 있으며, 드래그 중 Escape를 누르면 취소합니다. 순서는 로그인 계정별로 현재 브라우저에 저장해 새로고침 후에도 유지하고 같은 계정의 다른 창에도 반영합니다. 메뉴 순서 변경은 열어 둔 화면이나 입력 내용을 초기화하지 않습니다.

- `/dashboard`: 오늘 상태 대시보드
- `/calendar`: 연차, 반차, 미팅, 회사 일정 등록
- `/attendance`: 연차·오전/오후 반차·재택 일정 등록 및 캘린더 연동
- `/tasks`: JIRA 형태의 작업 등록 및 start/end date 기반 작업바 표시
- `/todos`: 오늘 TODO, 미완료 항목 자동 이월, 주간 보고서 생성
- `/projects`: 회사별 프로젝트 생성, 프로젝트별 회의록, 기록 및 파일 관리
- `/meetings`: 회의록 작성·조회·수정 및 Markdown 저장
- `/documents`: 폴더별 공용 문서와 파일 업로드·다운로드
- `/login`: 로그인
- `/admin`: 관리자 전용 사용자 계정 등록·조회
- `/chat`: 로그인 계정으로 참여하는 팀 채팅, 메시지 및 파일 공유
- `/receipts`: 등록된 영수증 사진, 등록자, 자동 등록일, 내용 조회
- `/receipt-upload`: 간단한 영수증 등록 전용 화면
- `/id-info`: 회사 공유 계정의 구분, ID, PWD, 기타 정보 등록·조회·수정·삭제
- `/pomodoro`: 집중 시간 설정, 아날로그 뽀모도로 타이머
- `/remote-work`: 날짜별 재택근무 내용 등록·조회·수정·삭제

## 연차·반차·재택

왼쪽 **연차·반차·재택** 탭에서 **+ 일정 등록**을 누르면 등록 팝업이 열립니다. 이름은 로그인 계정에서 자동으로 표시하며 구분, 날짜와 선택 메모를 입력합니다. 연차와 재택은 시작일·종료일로 기간을 지정하고, 반차는 하루의 **오전 / 오후**를 선택합니다. 근무 시간대를 가정하지 않고 캘린더의 일정 유형과 제목에 오전·오후를 표시합니다.

등록 즉시 같은 일정이 캘린더에 표시되며, 목록의 **캘린더 보기**를 누르면 해당 날짜와 일정 상세가 열립니다. 수정·삭제는 캘린더에서 처리하고 이 탭에도 반영됩니다. 월·구분별 조회, 전체 기간 조회, 25건씩 페이지 이동을 지원하며 기존 캘린더의 연차·반차·재택 일정도 함께 표시합니다.

별도 복사본을 만들지 않고 `vault/Calendar`의 기존 Markdown 일정으로 저장합니다. 따라서 Obsidian에서도 확인할 수 있고, 캘린더 수정·삭제 시 두 화면의 정보가 일치합니다. API는 `GET /api/attendance`, `POST /api/attendance`이며 기존 로그인 세션을 사용합니다.

## 재택근무 기록

왼쪽 메뉴의 **재택근무 기록**에서 **기록 등록**을 누르면 등록 팝업이 열립니다. 근무 날짜와 진행 내용을 입력하고 작성자는 로그인 이름으로 자동 표시됩니다. 근무 날짜는 한국 시간 기준 오늘로 기본 설정되며 다른 날짜도 선택할 수 있습니다. 진행 내용은 10,000자까지 입력하며 줄바꿈을 유지합니다. 기존 기록을 수정해도 원래 작성자를 유지합니다.

내용 입력창에서 **Ctrl+V**(맥은 **⌘V**)를 누르거나 **이미지 붙여넣기** 버튼을 클릭하면 클립보드에 복사한 이미지를 추가합니다. 버튼으로 클립보드에 접근할 수 없는 브라우저나 HTTP 접속 환경에서는 내용 입력창의 키보드 붙여넣기를 사용합니다. 일반 텍스트 붙여넣기는 그대로 지원합니다. **파일 첨부** 버튼으로 파일을 선택하거나 등록·수정 팝업에 파일을 **드래그 앤 드롭**해 여러 파일을 첨부할 수 있습니다.

클립보드 이미지는 JPG·PNG·GIF·WEBP를 지원하며, 이미지와 파일을 합쳐 최대 10개, 개당 20MB까지 첨부합니다. 저장 전에는 이미지 미리보기와 파일 목록에서 첨부를 취소할 수 있습니다. 저장된 기록의 사진을 누르면 원본을 새 탭에서 보고, 파일을 누르면 다운로드합니다.

기록은 근무 날짜가 최신인 순서로 표시하며, 근무 월이나 작성자·내용 검색으로 조회할 수 있습니다. 한 페이지에 25건씩 표시하고 목록의 **수정 / 삭제**로 관리합니다. 수정도 팝업에서 진행하며, 취소하면 기존 기록과 첨부를 유지합니다. 저장에 실패하면 입력 내용과 선택한 파일을 유지합니다. 저장 후에는 해당 근무 월의 목록으로 이동합니다.

데이터와 자동 등록·수정 시각, 첨부 정보는 서버의 `vault/RemoteWork/remote-work.sqlite3`, 파일 원본은 `vault/RemoteWork/Uploads/`에 보관합니다. 브라우저나 서버를 다시 열어도 유지하며, Git에는 포함하지 않습니다. 기존 텍스트 기록도 그대로 유지합니다. API는 `GET/POST /api/remote-work`, `PATCH/DELETE /api/remote-work/{id}`, 업로드는 `POST /api/remote-work/files`, 첨부 조회는 `GET /api/remote-work/files/{id}/preview`와 `/download`입니다. 등록 취소 시 미등록 업로드를 정리하며, 연결 중단 등으로 남은 미등록 파일은 24시간 경과 후 다음 업로드 시 정리합니다.

## 뽀모도로

왼쪽 메뉴의 **뽀모도로**에서 화면 중앙 시계의 바늘을 드래그하거나 아래 입력란에 집중 시간을 1~180분으로 입력합니다. 기본은 25분입니다. 로그인 이름이 자동 표시되며 시계 중앙 버튼으로 **시작**, **일시정지**, **재개**합니다. 일시정지한 뒤 시간을 조절하면 새 시간으로 설정됩니다. 입력란 옆 원형 화살표는 설정한 시간으로 초기화합니다. 실행 중에는 해당 실행의 이름을 유지합니다.

붉은 부채꼴 영역과 바늘이 남은 시간에 맞춰 줄어들며, 시계 중앙에 남은 분·초를 표시합니다. 숫자로 60분을 넘게 입력하면 눈금이 120분 또는 180분 기준으로 확장됩니다. 드래그는 현재 눈금 범위에서 조절하며 마우스와 터치를 지원합니다. 시계에 키보드 초점을 두고 방향키로 1분씩, Page Up/Down으로 5분씩 조절할 수도 있습니다.

설정과 진행 상태는 현재 브라우저에 저장합니다. 다른 메뉴로 이동하거나 새로고침해도 실제 종료 시각을 기준으로 이어지며, 같은 브라우저에서 연 ERP 창끼리는 상태를 동기화합니다. 브라우저 저장이 차단된 경우 현재 페이지 안에서만 유지됩니다. 다른 PC나 사용자와 타이머를 공유하지 않습니다.

집중 중 다른 ERP 탭으로 이동하면 오른쪽 아래에 남은 분·초와 빨간 막대가 표시됩니다. 막대는 설정 시간 대비 남은 비율만큼 채워지며 점점 줄어듭니다. 표시를 누르면 뽀모도로 탭으로 돌아가며, 일시정지·초기화·완료 상태에서는 숨겨집니다.

오른쪽 **실행 기록** 패널에는 이름, 실제 집중한 분·초, 목표 시간, 시작 시각과 진행 상태가 표시됩니다. **기록 숨기기 / 실행 기록 보기**로 열고 닫으며 이 선택도 기억합니다. 좁은 화면에서는 기록이 시계 아래에 표시됩니다. 시작한 실행부터 기록되며, 일시정지한 시간은 제외하고 재개할 때 같은 기록을 이어갑니다. 초기화하거나 시간을 변경하면 그때까지의 집중 시간을 ‘종료’ 상태로 남깁니다.

실행 기록은 `vault/Pomodoro/pomodoro.sqlite3`에 저장해 같은 ERP 사용자들이 함께 조회합니다. 25건씩 표시하며 최신 목록은 패널이 열려 있을 때 5초마다 갱신됩니다. 저장에 실패한 기록은 브라우저에 보관한 후 연결되면 같은 실행 ID로 재전송합니다. API는 `GET /api/pomodoro/history`, `PUT /api/pomodoro/history/{session_id}`입니다.

## Info

Info 탭은 ERP 로그인 후에도 별도 접근 비밀번호를 입력해야 열립니다. 비밀번호는 요청 시 지정한 값이며 서버에 PBKDF2 해시만 보관합니다. 관리자도 동일하게 확인해야 합니다. 주소와 기존 데이터 저장 위치는 유지합니다.

접근 인증은 현재 로그인 세션과 현재 탭에만 적용됩니다. 다른 메뉴로 이동하거나 새로고침하면 다시 입력하며, **잠금** 버튼으로 즉시 닫을 수 있습니다. 인증은 최대 30분 유지되고 로그아웃·로그인 만료 시 폐기됩니다. 목록·추가·수정·삭제·PWD 조회 API 모두 별도 인증을 요구하고, 접근 비밀번호나 인증 토큰을 브라우저 저장소에 남기지 않습니다. 10회 오입력 시 15분간 재시도를 제한합니다.

왼쪽 메뉴의 **Info**에서 **정보 추가**를 누르고 구분, ID, PWD, 기타 정보를 입력합니다. 구분만 필수라서 계정 없이 참고 정보만 기록할 수도 있습니다. 목록의 **수정**으로 내용을 변경하고, **삭제**를 누른 뒤 확인하면 해당 항목을 삭제합니다.

**등록 일시**와 **최종 변경 일시**는 서버에서 자동 기록하며 목록에 한국 시간(KST), 초 단위로 표시합니다. 처음 등록할 때는 두 시각이 같고, 수정 저장 시 등록 일시는 유지한 채 최종 변경 일시를 갱신합니다. 기존 항목도 저장된 시각을 표시합니다.

PWD는 기본적으로 가려져 있으며 **보기 / 숨기기**로 확인합니다. 수정 화면에서도 PWD는 가려진 상태로 입력되고, 비워서 저장하면 기존 PWD가 삭제됩니다. 저장 실패 시 입력 내용을 유지합니다.

데이터는 `vault/IdInfo/id-info.sqlite3`에 저장하고 Git에서 제외합니다. 일반 목록 API에는 PWD를 포함하지 않으며, PWD 확인과 수정 시 별도 요청으로 읽습니다. 이 데이터는 Markdown 노트 검색 대상에 포함되지 않습니다. 로그인과 Info 접근 인증을 모두 완료한 사용자는 공유 계정 PWD를 확인할 수 있습니다. 화면의 가리기는 표시 기능이며, 공유 계정 PWD는 로컬 DB에 평문으로 저장됩니다. ERP 로그인·Info 접근 비밀번호의 해시 저장과는 별도 기능입니다.

## 영수증 등록 사이트

ERP와 같은 서버·포트에서 제공하는 간단한 등록 전용 화면입니다. 다음 명령 한 번으로 ERP와 영수증 등록 화면을 함께 실행합니다.

```powershell
python run.py
```

기본 주소는 다음과 같습니다.

- ERP 영수증 탭: `http://127.0.0.1:8010/receipts`
- 영수증 등록 사이트: `http://127.0.0.1:8010/receipt-upload`

등록 사이트에서 **영수증 사진 여러 장과 내용**을 입력하면 등록자는 로그인 이름으로 자동 채워집니다. 한 번에 최대 20장까지 선택하고 추가 선택·사진별 미리보기·목록에서 제외할 수 있습니다. **선택한 사진 전체를 영수증 1건으로 묶어 저장**합니다. 예를 들어 사진 3장을 선택하면 목록에는 영수증 1건이 표시되고, 그 안에 사진 3장이 포함됩니다. 등록일과 시간은 서버가 한국 시간으로 자동 기록합니다. JPG, PNG, WEBP, GIF 사진을 **사진당 10MB**까지 등록할 수 있고, 내용은 4,000자까지 입력할 수 있습니다.

**사진 N장으로 영수증 1건 등록하기**를 누르면 모든 사진을 함께 전송하고 등록 상태를 표시합니다. 사진 하나가 잘못되거나 저장에 실패하면 일부만 등록하지 않고 전체 요청을 실패 처리합니다. **영수증 다시 등록하기**는 처음 선택한 사진·이름·내용·요청 ID를 유지하므로 응답 유실 후에도 중복 저장하지 않습니다. 사진이나 내용을 바꿔 등록하려면 **다른 영수증 등록하기**를 누릅니다.

ERP의 **영수증** 탭은 대표 사진·첨부 장수·등록자·등록 일시·내용을 최신순으로 한 줄씩 표시합니다. 행이나 **보기** 버튼을 누르면 팝업에서 작은 사진을 선택해 각 사진과 파일명을 확인합니다. **원본 보기**는 선택한 사진을 새 창에서 열고, **이 사진 다운로드**는 해당 원본만 내려받습니다. 목록의 **다운로드** 버튼은 사진이 한 장이면 바로 다운로드하고 여러 장이면 사진 선택 팝업을 엽니다. 팝업은 **닫기**, Esc 또는 바깥 영역 클릭으로 닫습니다. 한 페이지에 24건씩 표시하며 첫 페이지는 10초마다 갱신됩니다. 팝업을 보는 동안에는 자동 갱신을 잠시 멈춥니다. **새로고침**으로 최신 목록을 확인하고 **+ 영수증 등록**으로 `/receipt-upload`에 이동합니다.

상세 팝업의 **수정**에서 내용과 사진을 변경하고 **변경사항 저장**으로 반영합니다. **사진 전체 교체**에서 새 사진을 선택하면 기존 사진 전체를 선택한 사진들로 교체합니다. 선택하지 않으면 모든 기존 사진을 유지하며 등록자와 최초 등록 일시는 바뀌지 않습니다. **취소**하면 기존 기록으로 돌아가고, 저장 실패 시 입력 내용을 유지합니다. **삭제**는 확인 후 해당 영수증과 모든 첨부 사진을 함께 제거합니다. 로그인 사용자가 공용 영수증을 수정·삭제할 수 있습니다.

ERP 서버는 `config.yaml`의 `vault.path`를 사용합니다. 등록 정보는 `vault/Receipts/<영수증 ID>/receipt.json`, 원본 사진은 같은 폴더의 `image.*`, `image-<사진 ID>.*`에 저장되며 Git에는 포함되지 않습니다. 모든 사진과 등록 정보가 저장된 후에만 ERP 목록에 나타납니다. 기존 단일 사진 기록은 변환 없이 조회·수정할 수 있습니다. 백업할 때는 `vault/Receipts` 폴더 전체를 복사하면 됩니다.

접속 IP와 포트는 `config.yaml`의 `server.host`, `server.port`로 함께 설정합니다. 다른 PC나 휴대폰에서 이용하려면 `server.host`를 `0.0.0.0` 또는 서버 PC의 내부 IP로 설정하고, 같은 네트워크에서 `http://<서버 PC IP>:8010/receipt-upload`로 접속합니다. 포트를 변경했다면 해당 포트를 사용하고, 방화벽에서 ERP 포트를 허용해야 합니다. 일반 계정은 로그인 후 요청했던 영수증 등록 화면으로 돌아옵니다.

같은 ERP 서버에서 `POST /api/receipts`로 등록하고 `GET /api/receipts`로 목록을 조회합니다. 여러 사진은 `multipart/form-data`의 `metadata`(등록 시 `submission_id`, `content`, 선택적 `registrant`를 담은 JSON 문자열)와 반복되는 `images` 파일 필드로 전송합니다. 응답의 `images` 배열에 사진별 파일명·크기·원본 URL을 제공하며 `GET /api/receipts/{id}/images/{image_id}`로 개별 원본을 조회합니다. URL에 `?download=true`를 붙이면 다운로드합니다. `PATCH /api/receipts/{id}`도 같은 형식으로 내용(`metadata.content`)과 선택적인 사진 전체 교체를 지원합니다. 기존 단일 사진 JSON 요청(`filename`, `image_base64`), 내용만 수정하는 JSON 요청, 대표 사진 조회(`GET /api/receipts/{id}/image`)도 호환됩니다. `DELETE /api/receipts/{id}`는 영수증과 모든 사진을 삭제합니다. 업데이트 시 `python -m pip install -r requirements.txt`로 업로드 처리 의존성을 설치합니다.

## 자료실

PUBLIC의 **자료실**(`/documents`)에서 **새 폴더**를 누르고 제목(필수, 140자)과 내용 설명(선택, 3,000자)을 입력합니다. 폴더를 선택하면 설명과 파일 목록을 확인하고 폴더 제목·설명을 수정할 수 있습니다.

**파일 업로드** 또는 드래그 앤 드롭으로 이미지, PDF, PPT/PPTX, 엑셀, 압축 파일 등 형식 제한 없이 여러 파일을 올립니다. 파일당 최대 1GB(1,024MB)이며 같은 이름의 파일도 별도로 보관합니다. 업로드 진행 상황과 실패한 파일을 표시하고 실패한 항목만 다시 시도할 수 있습니다. 파일은 최신 업로드 순으로 표시하고 이름, 크기, **업로드 일시(한국 시간)**를 확인할 수 있습니다. PNG·JPG·GIF·WEBP는 이미지 미리보기도 제공합니다. 파일명을 누르거나 **다운로드**를 선택하면 원본을 내려받습니다.

로그인한 사용자들이 폴더와 파일을 함께 조회·관리합니다. 파일은 확인 후 삭제하며, 폴더는 내부 파일을 모두 삭제한 뒤 삭제할 수 있습니다. 폴더 정보와 파일별 업로드 시각은 `vault/Documents/documents.sqlite3`, 원본은 `vault/Documents/Uploads/`에 보관합니다. 새로고침·서버 재시작 후에도 유지하며 Git에는 포함하지 않습니다.

기존 위키 메뉴·화면·API는 제거했습니다. 기존 `vault/Wiki` 원본 노트는 디스크에 보존하지만 앱과 상담봇 검색에는 노출하지 않습니다.

## 회의록 수정

회의록 메뉴에서 목록의 **수정** 버튼을 누르거나, 문서를 선택한 뒤 오른쪽 **수정** 버튼을 누릅니다. 기존 내용과 이미지를 편집하고 하단의 **회의록 수정** 버튼으로 저장합니다. **취소**하면 저장된 문서로 돌아가며, 새 문서는 목록 상단의 **새 회의록**에서 작성합니다.

수정 시 기존 문서 ID, 프로젝트 연결, 첨부 이미지와 변경 이력을 유지합니다. 저장 요청이 실패하면 입력 내용이 남아 있어 다시 시도할 수 있습니다.

회의록의 **안건·회의 내용**, 프로젝트 **기록**에서 **Ctrl+V**(맥은 **⌘V**)로 복사한 이미지를 붙여넣으면 **이미지 삽입** 버튼과 같은 방식으로 원본을 서버에 저장합니다. 여러 이미지를 순서대로 업로드하며 저장·새로고침·재수정 후에도 본문 위치와 이미지 크기를 유지합니다. JPG·PNG·GIF·WEBP, 이미지당 10MB까지 지원합니다. 업로드 중이거나 실패한 이미지가 있으면 문서 저장을 막고, 실패한 이미지에는 **다시 시도 / 삭제** 버튼을 표시합니다. 웹 문서에서 복사한 이미지와 텍스트도 함께 붙여넣을 수 있으며 원본을 읽을 수 없는 이미지는 파일로 직접 첨부합니다.

팀 채팅 작성창과 영수증 등록 화면에서도 Ctrl+V로 이미지를 기존 첨부 목록에 추가할 수 있습니다. 프로젝트 **자료**의 업로드 영역에서도 이미지 붙여넣기를 지원합니다. 각 화면의 기존 파일 크기·개수 제한을 적용하며, 재택근무 기록의 이미지 붙여넣기도 계속 사용할 수 있습니다.

### 회의 회사 등록·선택과 회사별 조회

회의록 작성·수정 화면의 **회의 회사**에서 등록된 회사를 선택합니다. 처음 이용하는 회사는 **+ 회사 등록**을 눌러 회사명을 입력한 뒤 **등록 후 선택**을 누릅니다. 작성 중인 본문과 사진을 유지한 채 회사가 선택되며, 일반 회의록 화면과 프로젝트 안의 회의록에서 같은 회사 목록을 사용합니다.

프로젝트 안에서 회의록을 작성하면 **새 프로젝트에서 입력한 회사명**이 기본으로 적용됩니다. 저장할 때 해당 회사가 자동 등록되거나 기존 회사와 연결되고, 같은 회의록이 **회의록 → 회사별 보기**에도 나타납니다. 다른 회사를 직접 선택할 수도 있습니다. 두 화면은 같은 기록을 사용하므로 수정·삭제가 함께 반영됩니다.

회사명은 앞뒤 공백과 연속 공백을 정리하고, 영문 대소문자 및 전각·반각 차이만 있는 이름은 기존 회사로 연결합니다. 회의록은 회사의 고유 ID와 등록된 이름을 함께 저장합니다.

회의록 목록의 **회사별 보기**에서 전체 회사, 특정 회사, 회사 미지정을 선택할 수 있습니다. 필터는 주소에도 반영되어 새로고침하거나 해당 주소를 다시 열어도 유지됩니다. 기존 프로젝트 회의록 중 회사 미지정 항목은 서버 시작 시 프로젝트 회사명으로 연결되며, 이미 선택된 회사는 유지합니다. 프로젝트 회사명이 없는 기록은 **수정**에서 회사를 연결할 수 있습니다. 회사 연결만 바꾸면 기존 본문·사진·프로젝트 연결·변경 이력을 보존합니다.

회사 목록은 `vault/Companies/companies.sqlite3`, 회의록의 회사 연결은 기존 `vault/Meetings` Markdown 파일에 저장됩니다. `GET /api/companies`, `POST /api/companies`로 회사 목록을 조회·등록하며, `GET /api/meetings?company_id=<회사 ID>`로 회사별 회의록을 조회합니다. `company_id=`는 미지정 회의록이며 `project_id`와 함께 필터링할 수 있습니다.

## 팀 채팅

왼쪽 메뉴의 **팀 채팅**을 열면 로그인 계정으로 공용 **팀 라운지**에 바로 참여합니다. 별도 이름 입력·변경 없이 채팅방 상단, 메시지 작성자, 참여자 목록과 공유 파일 작성자를 **이름_직함**(예: `김민수_대리`)으로 표시합니다. 다른 브라우저에서 같은 계정으로 로그인해도 같은 작성자로 연결됩니다. 새 메시지는 전송 당시의 이름과 직함을 함께 보관하며, 기존 계정에 연결된 메시지도 직함을 표시합니다. 로그인 도입 전 계정에 연결되지 않은 메시지는 기록된 이름을 유지합니다.

- 메시지는 약 2.5초마다 자동으로 갱신됩니다. Enter로 보내고 Shift + Enter로 줄을 바꿉니다.
- 첨부 버튼이나 작성창에 파일을 끌어놓아 공유합니다. 메시지 없이 파일만 보낼 수도 있습니다.
- 파일당 최대 20MB, 메시지당 최대 5개, 메시지 본문 최대 4,000자를 지원합니다.
- 파일은 메시지와 우측 최근 공유 파일 목록에서 다운로드합니다.
- 전송이 실패하면 작성한 내용과 첨부 파일을 유지합니다. 같은 요청의 재시도는 중복 저장하지 않습니다.
- 최근 대화부터 표시하며 **이전 대화 보기**로 과거 기록을 불러옵니다.
- 본인이 보낸 메시지를 **전송 후 2분 이내 우클릭**하면 **수정 / 삭제** 메뉴가 나타납니다. 키보드는 메시지에 초점을 두고 Shift+F10을 사용합니다.
- 수정 팝업에서 본문을 저장하고, 삭제는 확인 팝업에서 처리합니다. 수정해도 최초 전송 기준 2분 제한은 연장되지 않으며 서버가 작성자와 시각을 확인합니다.
- 수정된 메시지에는 ‘수정됨’, 삭제된 메시지에는 ‘삭제된 메시지입니다.’가 표시됩니다. 삭제한 메시지의 첨부는 공유 목록과 다운로드에서 제외됩니다. 다른 참여자의 화면에도 자동 반영됩니다.
- 공용 채팅의 기록과 파일은 로그인한 ERP 사용자끼리 공유합니다.

기존 우측 하단의 **노트 상담봇**은 별도 기능으로 유지됩니다. 다른 PC에서 같은 채팅방을 사용하려면 `config.yaml`의 `server.host`를 해당 PC에서 접근할 수 있는 주소로 설정하고 동일한 ERP 서버에 접속해야 합니다.

## 저장 방식

프로젝트, 작업, 일정 등 업무 데이터는 `vault/` 아래 Markdown 노트로 저장됩니다. 각 노트는 YAML 스타일 frontmatter를 포함하므로 Obsidian에서 바로 열 수 있고, LLM Wiki 형태로 폴더별 검색과 요약이 가능합니다. 회의록과 프로젝트 기록의 첨부 이미지는 `vault/Assets`에 저장됩니다.

팀 채팅은 동시 전송과 대화 순서를 보장하기 위해 `vault/Chat/chat.sqlite3`에 메시지와 계정별 참여 정보를 저장합니다. 공유 파일은 `vault/Chat/Uploads`에 저장하며, 채팅 데이터는 Git에서 제외됩니다. 기존 대화는 로그인 도입 후에도 유지됩니다.

## 주요 API

- `GET /api/dashboard`
- `GET /api/calendar`, `POST /api/calendar/events`
- `GET /api/tasks`, `POST /api/tasks`, `PATCH /api/tasks/{task_id}`
- `GET /api/todos`, `POST /api/todos`, `PATCH /api/todos/{todo_id}`, `POST /api/todos/weekly-report`
- `GET /api/projects`, `POST /api/projects`, `PATCH /api/projects/{project_id}`
- `GET /api/meetings`, `POST /api/meetings`
- `GET/POST /api/documents/folders`, `PATCH/DELETE /api/documents/folders/{id}`
- `GET/POST /api/documents/folders/{id}/files`, `DELETE /api/documents/files/{id}`
- `GET /api/documents/files/{id}/download`, `GET /api/documents/files/{id}/preview`
- `GET /api/id-info`, `POST /api/id-info`, `PATCH /api/id-info/{id}`, `DELETE /api/id-info/{id}`
- `GET /api/id-info/{id}/password`
- `POST /api/auth/login`, `GET /api/auth/me`, `POST /api/auth/logout`
- `GET /api/admin/users`, `POST /api/admin/users` (관리자 전용)
- `GET /api/team-chat/session`
- `GET /api/team-chat/messages`, `POST /api/team-chat/messages`
- `PATCH /api/team-chat/messages/{id}`, `DELETE /api/team-chat/messages/{id}`
- `GET /api/team-chat/files`, `POST /api/team-chat/files`, `GET /api/team-chat/files/{file_id}/download`

모든 데이터 API는 로그인 응답의 HttpOnly 세션 쿠키를 사용합니다. 파일 업로드는 `filename`, `upload_id` 쿼리와 파일 원본 바이트를 본문으로 전송합니다. `upload_id`와 메시지의 `client_id`는 재시도 시 동일한 UUID를 사용합니다. 대화 목록은 `after` 또는 `before` 메시지 ID로 페이지를 조회하고, `since_change`에 마지막 `change_cursor`를 전달하면 이미 읽은 메시지의 수정·삭제도 조회합니다.

API 문서는 서버 실행 후 `{server.host}:{server.port}/docs`에서 확인할 수 있습니다. 기본 설정에서는 `http://127.0.0.1:8010/docs`입니다.

## 테스트

```powershell
python -m pip install -r requirements-dev.txt
python -m unittest discover -s tests -v
node --test tests/test_*.mjs
```

테스트는 임시 저장소에서 실행하며 실제 Vault 데이터를 변경하지 않습니다.

이미지 붙여넣기 브라우저 테스트(`tests/test_image_paste_browser.py`)는 Playwright와 Chromium이 설치된 환경에서 실행하며, 미설치 환경에서는 해당 테스트만 건너뜁니다. 실제 Ctrl+V, 업로드 실패·재시도, 저장 후 새로고침·재수정, 프로젝트·채팅·영수증 첨부를 검사합니다.
